# 사장님, 전설이 되다

창업 준비자의 법률·세무 질문에 공식 자료를 검색해 답하고, 앞선 대화의 맥락을 이어가는 한국어 RAG 챗봇입니다.

**2026.03–2026.06 · 고려대학교 세종캠퍼스 · 4인 팀 프로젝트**

## 프로젝트와 기여

이선재는 팀장으로 코딩 전반을 담당했습니다. 팀원들은 내용 정리, 발표자료 제작, 발표를 담당했습니다. 기본 RAG 구현 과제에서 멀티턴 대화와 웹 배포를 추가 목표로 제안했습니다. 마감이 가까워 기본 기능에 집중하자는 의견이 있었지만, 짧은 시간에 구현할 수 있다는 설명으로 동의를 얻었습니다. 실패하면 기본 기능으로 돌아갈 수 있다는 판단 아래 추가 개발에 도전했습니다. 실제 롤백을 수행했다는 의미는 아닙니다.

Netlify를 활용해 발표 참가자가 각자의 컴퓨터에서 서비스를 체험하도록 배포했습니다(작성자 경험 기록). **당시 Netlify 설정·웹 소스·백엔드 연결 구성 및 배포 URL은 이번 원본 폴더에 포함되지 않았습니다.** 이 저장소는 확인 가능한 노트북과 로컬 데모, 데이터 및 실험 기록을 정리한 것입니다.

## 핵심 기능

- 726개 문서와 31개 카테고리를 바탕으로 한국어 의미 검색
- 문장 단위 청킹, 긴 문장 분할, 제목을 포함한 임베딩
- `jhgan/ko-sroberta-multitask` + 정규화 벡터 + FAISS `IndexFlatIP`
- 이전 사용자 질문 최대 3개를 반영하는 질의 재작성과 최근 3턴의 생성 이력
- 유사도 임계값으로 검색 결과 선별, 근거 중심 답변, 출처·유사도 표시
- API 키가 없으면 직전 질문 결합 및 원문 검색 결과 안내로 전환

## 2026년 9월 배포 구성 보완

현재 코드에 맞춘 Netlify 프런트엔드와 Python API, Dockerfile을 추가했습니다. 실제 모델을 사용한 로컬 검색·후속 질문·자료 밖 질문과 브라우저 동작을 확인했습니다(API 키 없는 모드). 과거 배포 파일은 확보되지 않아 **신규 보완 버전**으로 기록합니다. 실제 공개 운영에는 Python 호스팅 URL이 필요합니다. [실행·배포 안내](docs/deployment.md) · [배포 구조도](docs/deployment-architecture.html)

## 실행

Python 가상환경을 만든 뒤 저장소 루트에서 실행합니다. 아래 의존성 목록은 원본 import를 기준으로 정리했으며, 당시의 버전 잠금 파일은 확보되지 않았습니다.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
jupyter lab RAG_Chatbot.ipynb
```

**전체 RAG·멀티턴 구현은 `RAG_Chatbot.ipynb`가 기준**입니다. 저장소 루트를 작업 디렉터리로 두고 위에서부터 실행합니다. `RUN_CHUNKING=False`가 기본이라 동봉된 JSONL을 사용합니다. PDF 재수집·청킹은 선택 단계이고 원본 PDF 및 Poppler가 필요합니다.

LLM 생성 모드는 Jupyter를 시작하기 전에 `OPENAI_API_KEY` 환경변수를 설정합니다. 키를 파일에 적지 않습니다. 설정하면 OpenAI API를 호출하며 비용이 발생할 수 있습니다. 첫 실행에는 Hugging Face 임베딩 모델 다운로드도 필요합니다.

검색 전용 미리보기:

```bash
python scripts/demo_retrieval.py
```

기본 주소는 `http://127.0.0.1:7861`입니다. 이 스크립트는 Gradio의 로컬 검색 결과 안내판으로, **API 키가 있어도 LLM을 호출하지 않습니다.** 전체 노트북의 LLM 질의 재작성 및 생성 모드와 구분합니다. 데이터 변경 시 `.cache/demo.pkl`을 지워 인덱스를 다시 생성합니다.

## 저장된 실험 결과

아래는 원본 노트북에 저장된 실행 출력입니다. 저장소 정리 과정에서 모델/API를 다시 실행해 얻은 값이 아닙니다.

| 항목 | 조건 | 기록된 결과 |
|---|---|---|
| 데이터 | 입력 JSONL → 문서 복원 | 3,089개 → 726개 / 31개 카테고리 |
| 검색 청크 | 180자 설정 | 8,945개 |
| 청크 비교 | 100 / 180 / 300자, 18문항 | Hit@3 0.778 / 0.889 / 0.944 |
| 최종 검색 | 180자, top-k=5, 18문항 | Hit@5 1.000 / MRR 0.821 |
| 임계값 | 도메인 내 평균 0.703 / 외 평균 0.302 | 0.53 |
| 답변 키워드 포함 | 튜닝 18문항 | 18/18 |
| 별도 검증 | 답변 4문항 + 거절 2문항 | 6/6 |
| 멀티턴 예시 | 미용실 맥락, 후속 질문 2개 | 다른 업종 검색 → 미용실 관련 자료 검색 |

Hit@k와 MRR은 **정답 키워드가 포함된 청크의 검색 순위**로 계산합니다. 작은 자체 평가셋의 결과이며 서비스 전체 정확도나 법률 판단의 정확도를 뜻하지 않습니다. 180자 설정에도 128토큰을 초과한 청크가 106개 있었습니다. 300자 설정의 검색 점수는 더 높았지만 입력 잘림과 문맥 길이를 고려해 180자를 선택한 기록입니다.

자세한 평가: [평가와 한계](docs/evaluation.md) · [원본 출력 발췌](docs/recorded-results.json)

## 구조도

[인터랙티브 구조도 HTML](docs/architecture.html)을 내려받아 브라우저에서 열면 확대·검색·테마 전환이 가능합니다. GitHub 파일 화면은 HTML을 실행하지 않습니다.

구조도는 노트북의 논리 흐름이며 Netlify 배포 인프라를 추정해서 그리지 않았습니다. 본문은 한국어, Archify 뷰어의 고정 메뉴와 HTML 언어 설정은 영어 기본값입니다.

## 파일 구성

- `RAG_Chatbot.ipynb`: 원본 실행 논리와 설명, 출력은 제거한 공유용 노트북
- `scripts/demo_retrieval.py`: 경로를 상대화하고 모드 표시를 바로잡은 검색 전용 미리보기
- `data/`: 문서 CSV와 원본 전처리 JSONL
- `docs/evaluation.md`: 평가 정의·표본 수·한계
- `docs/provenance.md`: 원본과 정리본의 차이 및 확인 범위
- `docs/architecture.html`, `docs/architecture.json`: Archify 구조도와 원본 명세
- `tests/test_contract.py`: 외부 모델/API 없이 실행하는 핵심 분기·자료 검사

## 데이터와 한계

데이터는 프로젝트 당시의 국세청, 중소벤처기업부, 법제처 관련 자료를 정리한 스냅샷입니다. 원자료 제목과 출처는 `source` 열을 따릅니다. 법령·지원 조건은 현재와 다를 수 있으며, 이 프로젝트는 전문 상담을 대체하지 않습니다. 원문 자료에 대한 별도의 재라이선스를 부여하지 않습니다.

유사도만으로 자료의 충분성을 보장할 수 없으며, 맥락에 없는 사업 질문이 임계값을 통과할 수 있습니다. 질의 재작성에는 추가 API 호출이 필요하고, 직전 질문 결합 방식은 주제 전환에 취약합니다. 자료 갱신, 평가 확장, 배포 구성 복원이 후속 과제입니다.
